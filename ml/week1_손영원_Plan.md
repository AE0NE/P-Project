## 1. 이번 주에 내가 책임지는 것

PM으로서는 **팀이 같은 문제와 같은 결과 형식을 기준으로 개발하게 만드는 것**을 책임집니다. AI 담당자로서는 **모델이 배울 정답과 규칙·모델을 비교할 방법을 만드는 것**을 책임집니다.

| 역할 | 이번 주 내가 할 일 | 다른 담당자와 나눌 일 |
| --- | --- | --- |
| PM | 범위 합의, 완료 기준 작성, 막힌 일 조정, 통합 결과 확인 | 화면·서버·파싱을 전부 대신 구현하지 않음 |
| AI·평가 | 주석 지침, 정답 교차 검수, 추출 결과 형식 검토, 평가 설계 | 원문 확보와 주석은 공동 작업으로 배분 |

이번 주 핵심 결과는 다음과 같습니다.

> **팀이 같은 기준으로 정답을 표시할 수 있고, 같은 형식으로 결과를 주고받으며, 문서 한 건을 처리하는 흐름과 비교 실험을 시작할 수 있다.**

F1 0.80 달성이나 최종 모델 선정은 첫 주 완료 기준으로 두지 않습니다. 기존 목표 수치는 유지하되, 지금은 그 성능을 제대로 측정할 토대를 만듭니다.

## 4. 실제 자료와 정답 기준 만들기

### W1-02 자료 후보와 파일럿 지정

박신혁 님과 자료 후보를 확인하고, 내가 선정 기준과 개발·평가에서 사용할 범위를 정리합니다.

1. 공식 자료를 확인할 수 있는 일반 신용카드 후보 목록을 만듭니다.
2. 상품별로 공식 URL, 문서 종류, 수집·적용 시점, 자료 버전을 기록합니다.
3. 열람·확보·학습·자동수집·재배포의 이용조건 확인 상태를 구분합니다.
4. 사용할 수 있는 자료 중 우선 1~2개 상품을 학습용 파일럿으로 지정합니다.
5. 최종 12개 상품군의 학습 7·검증 2·시험 3 분할 초안을 작성합니다.

후보 12개와 확보 완료 12개를 구분합니다. 이용조건이 불명확한 자료를 확보 완료나 학습 가능으로 기록하지 않습니다.

파일럿으로 개발에 반복 사용한 상품은 이후 최종 시험군으로 옮기지 않습니다. 같은 상품의 HTML·PDF·개정본과 유사 변형은 같은 집합에 둡니다. 최종 목록이 미정이면 미정인 이유를 기록하되, 파일럿 상품의 학습용 배정은 분명하게 남깁니다. 시험 자료를 보고 모델·규칙을 고치지 않습니다.

**완료 증거:** 후보 목록, 실제 확보·이용조건 상태, 파일럿 상품 ID, 분할 초안과 미확정 사항.

### W1-03 주석 기준과 첫 정답 제작

주석은 원문에서 조건의 유형과 시작·끝 위치를 사람이 표시하는 작업입니다. 내가 기준 초안을 작성하고, 다른 팀원 한 명 이상과 독립적으로 표시한 결과를 비교합니다. 대량 주석 전에 다음 순서로 진행합니다.

1. 학습용 파일럿에서 제목·표 헤더·필요한 각주가 포함된 블록 5~10개를 준비합니다.
2. 두 사람이 서로의 답을 보기 전에 각각 주석합니다.
3. 다르게 표시한 범위·유형과 판단 이유를 비교합니다.
4. 원문을 보고 기준을 보완한 뒤 합의한 정답과 보류 사례를 남깁니다.
5. 기준을 적용한 실제 블록 10개 이상을 확인하고, 안정되면 초기 30~50개로 확대합니다.

여섯 라벨은 `TARGET`, `RATE`, `SPEND`, `LIMIT`, `SPEND_EXCL`, `BENEFIT_EXCL`입니다. 정의는 README를 따르되, 아래와 같은 경계 사례를 지침에 추가합니다.

| 합의할 질문 | 필요한 이유 |
| --- | --- |
| `30만 원`과 `30만 원 이상` 중 어디까지 선택하는가? | 금액과 적용 기준을 일관되게 표시하기 위해 |
| 한도에 `월`, `건당`, `합산`을 포함하는가? | 기간과 한도 범위가 빠지는 것을 줄이기 위해 |
| 제외 문구는 목록만 표시하는가, 제외를 뜻하는 표현까지 포함하는가? | 유형과 경계를 같은 기준으로 평가하기 위해 |
| 제외 목록 안의 업종을 TARGET으로도 중복 표시하는가? | 단일 BIO 태그가 중첩 구간을 직접 표현하지 못하기 때문에 |
| 제목과 공통 각주가 어느 혜택에 적용되는지 애매하면 어떻게 기록하는가? | 불명확한 관계를 임의로 정답 확정하지 않기 위해 |

주석 도구는 두 사람이 같은 원문에서 범위를 선택하고 결과를 기록할 수 있는 간단한 방식부터 정합니다. 도구를 만드는 데 시간을 쓰기보다 원문·문자 위치·주석자·조정 결과를 보존할 수 있는지 확인합니다.

연회비처럼 이번 여섯 조건에 해당하지 않는 숫자나 조건 없는 문장도 구분합니다. 모든 숫자를 조건으로 표시하거나 모든 블록에 반드시 정답이 있어야 한다고 가정하지 않습니다.

**내가 확인할 것**

- [ ] 보존한 블록 텍스트의 선택 구간과 주석 문구가 실제로 일치한다.
- [ ] 금액 정규화 결과와 원문 추출 구간을 섞어 기록하지 않았다.
- [ ] 두 사람의 최초 주석과 조정한 정답을 구분했다.
- [ ] 일치하지 않은 이유와 보류 건수를 기록했다.
- [ ] 이번 블록에서 나오지 않은 유형은 없다고 꾸미지 않고 실제 사례 수를 기록했다.

원문·실제 주석 파일은 저장소의 데이터 관리 원칙에 맞춰 보관하고, 공개 문서에는 허용된 자료와 직접 만든 예시를 사용합니다.

## 5. 다른 모듈과 연결할 기준 정하기

### W1-04 공통 입출력 형식 검토

박서연 님이 형식 초안을 작성하고, 나는 모델의 입력·출력과 평가에 필요한 정보가 있는지 확인합니다. 박신혁 님은 문서 처리 결과를 이 형식으로 만들 수 있는지, 박세렴 님은 근거 표시와 수정 화면에 사용할 수 있는지 확인합니다.

내가 반드시 확인할 내용은 다음과 같습니다.

- 입력에 상품·문서·블록 ID와 분석할 텍스트가 있는가?
- 제목·표 헤더가 입력에 포함되며 보존 원문으로 돌아갈 대응 정보가 있는가?
- 출력에 조건 유형과 원문 시작·끝 위치, 원문 값이 있는가?
- 문서 처리·규칙·모델이 같은 기준 문자열과 문자 단위를 사용하는가?
- 미확인과 명시적 없음, 처리 실패와 검토 상태를 구분할 수 있는가?
- 원래 예측과 사람의 수정 결과를 따로 저장할 수 있는가?

다음은 **직접 만든 형식 논의용 예시**입니다. 실제 상품이나 현재 구현 결과가 아닙니다.

```json
{
  "block_id": "SYN-B001",
  "text": "편의점 10% 할인",
  "spans": [
    {"type": "TARGET", "start": 0, "end": 3, "text": "편의점"},
    {"type": "RATE", "start": 4, "end": 7, "text": "10%"}
  ]
}
```

이 예시는 0부터 시작하고 끝 위치는 포함하지 않는 방식입니다. 예를 들어 `text[4:7]`은 `10%`입니다. 실제 공통 형식에서는 문자 단위도 명시하고, 브라우저와 Python에서 같은 구간을 가리키는지 확인합니다. PDF 좌표와 이 문자 위치는 별도의 대응이 필요합니다.

이 샘플을 합의한 뒤에는 필드 이름이나 라벨을 혼자 바꾸지 않습니다. 변경 이유와 영향을 먼저 공유합니다.

**완료 증거:** 합의한 샘플과 필드 정의, 각 담당자의 확인 결과, 남은 미정 항목.

## 6. 교수님 피드백을 이번 주 작업으로 옮기기

### W1-05 평가 설계와 지표 계산 확인

이번 주에는 비교 실험 초안과 지표 계산 방법을 정합니다. 모델 학습보다 먼저 측정 기준을 확인해야 나중에 결과를 공정하게 비교할 수 있습니다.

**추출 성능 비교**

- 비교 대상: 문맥을 활용하는 규칙 추출기와 학습 모델 추출기.
- 같은 조건: 본문·제목·표 헤더, 입력 지원 범위, 공통 정규화·관계 연결 후처리.
- 정답: 사람이 원문에서 검수한 조건 유형과 시작·끝 위치.
- 주 지표: 수정 전 예측의 Strict Span Micro-F1. 유형·상품군별 결과와 오류 수도 기록.
- 별도 확인: 정규화 값, 혜택 소속, 공유 한도 연결 오류.

첫 통합용 규칙은 단순하게 시작할 수 있습니다. 최종 비교에서는 학습·검증 자료로 충분히 보완한 규칙을 사용하며, 약한 규칙을 고의로 비교 대상으로 두지 않습니다.

**업무 효과 비교**

1. 원문을 읽고 수작업으로 조사표 작성.
2. 규칙 결과를 제공하는 검토 도구 사용.
3. 모델 결과를 제공하는 같은 검토 도구 사용.

두 도구는 추출기 외의 화면과 기능을 같게 하고, 세 조건의 필수 항목과 완료 기준을 맞춥니다. 과제와 수행 순서를 나눠 같은 문서를 다시 봐서 빨라지는 영향을 줄입니다. 시간과 함께 최종 누락·중요 오류·수정량·자동 채움률을 확인합니다. 이번 주에는 과제 예시와 비교 절차를 적고, 실제 사용자 실험은 이후 기능이 준비되면 진행합니다.

**내가 직접 확인할 지표 계산 예시**

앞의 합성 문장에 정답 두 개가 있다고 가정합니다.

- `TARGET`: 시작 0, 끝 3
- `RATE`: 시작 4, 끝 7

| 예측 사례 | TP | FP | FN | 기대 F1 |
| --- | --- | --- | --- | --- |
| 두 구간의 유형·범위가 모두 맞음 | 2 | 0 | 0 | 1.0 |
| TARGET은 맞고 RATE를 LIMIT으로 잘못 분류 | 1 | 1 | 1 | 0.5 |
| TARGET만 찾고 RATE를 놓침 | 1 | 0 | 1 | 약 0.6667 |
| TARGET은 맞고 RATE 끝을 6으로 잘못 예측 | 1 | 1 | 1 | 0.5 |

TP는 정확히 맞힌 구간, FP는 틀리거나 불필요한 예측, FN은 놓친 정답입니다. `F1 = 2TP / (2TP + FP + FN)`으로 손계산과 코드 결과를 대조합니다. 이 예시는 **계산기 점검용이며 모델 성능이 아닙니다.** 실제 평가는 블록별 점수를 단순 평균내지 않고 전체 TP·FP·FN을 합쳐 Micro-F1을 계산합니다.

**완료 증거:** 비교 절차 초안, 지표 코드·실행 결과, 위 예시와 일치하는 계산, 평가에 남은 질문.

교수님이나 멘토에게 확인할 질문도 정리합니다. 규칙과 학습 모델의 비교 외에 추가 비교 모델이 필요한지, 상품군 단위의 작은 시험 규모를 어떻게 보고할지, 학생 대상 업무 실험을 예비 평가로 제시하는 방식이 적절한지 확인할 항목으로 남깁니다. 확인 전에는 합의된 요구사항이나 승인받은 평가 방법으로 기록하지 않습니다.

## 7. 기준이 준비된 뒤 진행할 AI 실행 확인

다음 작업은 W1-02~05의 핵심 기준을 우선 정리한 뒤 진행합니다. 이번 주 안에 가능하면 수행하고, 못 했다면 이유와 환경 상태를 주간 보고에 남깁니다.

1. 사용할 Python·PyTorch·Transformers 환경과 실제 버전을 기록합니다.
2. KoELECTRA-Small 후보와 토크나이저를 불러올 수 있는지 확인합니다.
3. 카드 조건용 분류 출력을 13개 태그로 구성합니다.
4. 합성 예시 또는 이용 가능한 학습용 예시에서 토큰화·태그 정렬·원문 구간 복원을 점검합니다.
5. 준비한 정답이 충분하면 작은 학습 실행을 시도하고 로그를 보존합니다.

여기서 확인할 것은 학습·평가 경로가 실행되는지입니다. 같은 작은 자료를 학습하고 다시 맞힌 점수는 독립적인 검증 성능으로 보고하지 않습니다. 입력 256토큰도 초기 기준이며 특수 토큰과 제목·헤더를 포함한 실제 길이를 확인합니다.

모델 실행이 늦어져도 화면과 서버는 합의한 합성 샘플과 규칙 결과로 연결할 수 있습니다. 모델이 아직 없는 상태를 팀에 알려 다른 작업이 기다리지 않도록 조율합니다.

## 9. 팀장으로서 확인할 연결 지점

다른 담당자의 세부 개발은 각자 진행합니다. 나는 결과가 서로 연결되는지 확인합니다.

| 담당자 | 내가 받아 확인할 결과 | 내가 함께 결정하거나 전달할 내용 |
| --- | --- | --- |
| 박신혁 | 원문과 블록·위치 대응, 초기 규칙 출력 | 필요한 문맥·라벨 기준, 규칙 비교 조건 |
| 박서연 | 공통 형식, 결과 조회·수정 저장 방식 | 최초 예측 보존, 조건 상태와 검토 상태, 평가용 출력 |
| 박세렴 | 근거 확인·수정·저장 흐름 | 사람이 수행할 검토 과제와 완료 기준 |

작업마다 담당자 한 명, 확인할 결과, 목표일을 둡니다. 공통 주석도 작업할 사람과 교차 검수할 사람을 지정합니다. ‘공동 업무’라는 이유로 내게 전부 몰리지 않게 합니다.

매 작업일에는 완료한 결과, 다음 결과, 막힌 이유를 짧게 기록합니다. 중간 연결 확인은 11/4, 전체 흐름 확인은 11/7을 기본으로 잡고 팀 일정에 맞춰 합의합니다.

## 12. 다음 주로 넘어가기 위한 판정

### 데이터 확대와 초기 모델 실험을 진행할 조건

- [ ] 사용할 수 있는 학습용 파일럿 자료와 출처가 있다.
- [ ] 실제 블록 10개 이상을 두 사람이 독립 주석하고, 조정·보류를 기록했다.
- [ ] 다른 사람이 적용할 수 있는 주석 지침 초안이 있다.
- [ ] 팀이 같은 입력·출력 예시와 위치 기준을 이해한다.
- [ ] 지표 계산이 손계산 예시와 일치하고 비교 실험 초안이 있다.
- [ ] 시험 자료를 개발에 사용하지 않을 분할 원칙과 파일럿 배정을 기록했다.

이 기준을 통과하면 다음 주에 주석 확대, 규칙 보완, 초기 모델 학습·검증을 구체화합니다. 통합에서 남은 문제는 담당자와 수정일을 정해 병행합니다.

기준이 미달하면 부족한 기준을 먼저 보완하고, 독립적으로 가능한 다른 작업은 계속 진행합니다. 실제 자료·정답·공통 형식이 준비되지 않은 채 학습량이나 기능 수부터 늘리지는 않습니다.
