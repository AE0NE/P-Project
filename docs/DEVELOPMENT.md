# 개발 시작 안내

현재 저장소는 코드와 실험을 함께 관리하기 위한 초기 골격입니다.
먼저 최소 흐름을 연결하고, 실제 구현을 검증한 뒤 설치·실행 안내를 보완합니다.

## 첫 작업 제안

| 영역 | 첫 작업 | 완료 기준 |
| --- | --- | --- |
| 공통 | 상품 선정 및 문서 출처 목록 | 선정 기준·상품 식별자·공식 URL·수집일 기록 |
| AI | 라벨링 지침과 상품 분할 | 여섯 라벨 정의·경계 사례·고정 분할표 작성 |
| 전처리 | 문맥 블록과 원문 위치 보존 | 본문·표·유의사항을 근거 위치와 함께 읽는 예시 |
| 백엔드 | API·DB 명세 | 문서·혜택·조건·근거·검토 이력을 표현하는 스키마 |
| 프론트엔드 | 검토 화면 목업 | 원문과 조건을 함께 보고 수정·승인하는 흐름 |
| 통합 | 합성 예시 1건 연결 | 입력 → 구조화 결과 → 검토 → 비교·CSV 경로 확인 |

## 데이터 계약에서 먼저 정할 것

- 문서: 상품·버전·출처 URL·수집일·파일 해시
- 문맥: 블록 식별자·본문·페이지·오프셋 등 원문 위치
- 혜택: 혜택 식별자·종류·대상·결제 경로
- 조건: 유형·원문 값·정규화 값·단위·연산자·적용 혜택·한도 범위
- 상태: 추출 상태(`추출됨` / `미확인` / `명시적 없음` / `검토 필요`)와 검토 상태를 별도 관리
- 이력: 최초 예측·수정값·승인 결과를 분리 보존

`미확인`은 모델이 찾지 못했다는 뜻이며, 해당 조건이 없다는 뜻으로 해석하지 않습니다.
충돌하는 조건과 모호한 한도 관계는 임의로 결정하지 않고 원문 확인 대상으로 표시합니다.

## 실험 기록 항목

실험 ID, 코드 커밋, 데이터 버전·분할, 모델·토크나이저 버전, 시드, 하이퍼파라미터,
후처리 버전, strict span P/R/F1, 라벨별 지표, 연결 오류, CPU 장비와 p95, 메모리를 기록합니다.
CPU warm 추론과 문서 전체 처리시간은 분리합니다. 검토 실험은 최종 품질을 확인하면서 시간을 비교합니다.
